## Checked and fine

Radiogroup: Mantine's SegmentedControl renders `role="radiogroup"` with native radio inputs (confirmed in `node_modules`), `aria-label="Workflow view"` is passed to the group, one tab stop, Arrow keys move and select, focus ring is native `:focus-visible`; the view is written with `replaceState` so Back is not polluted; both labels are plain words. Reorder buttons are real `<button>`s with names that include the row name, tooltips duplicate rather than replace them, and the panel has Show/hide as a real Switch. Panel and graph take every colour from `--rb-ed-*` or Mantine tokens (no new hex, nothing defined or edited in the editor's set; light and dark both resolve); the restyle only recolours and keeps layout and sizes. Node is a focusable `role="button"` with Enter/Space and a name `Step n, type: label`; Delete and Settings have `stopPropagation` and names. Error alert in the panel uses `role="alert"`; the Save button has a loading state; `aria-expanded` and `aria-controls` on the inputs toggle. Run page: 44 px segments, file rows, buttons and the sticky bar with safe-area inset and `scroll-margin-bottom`; status, readiness and result regions are polite live regions; every state carries a word and an icon (never colour alone); blocked Run is `aria-disabled` with a reason and a dashed edge; failed banner says what happened and offers Resume, Retry, Ask the assistant; skeleton uses `min-height: 100dvh`; no em-dashes found in the run page strings; no ids or step names are shown to the user.

Verdict: fail (3 blockers, all WCAG 1.4.3 text contrast on Mantine default dimmed, red and orange text, each fixable with a class or a prop change; then pass-with-fixes). Confidence: high on the contrast figures (computed from the Mantine default palette and the `global.css` tokens; if the app theme overrides dimmed/red/orange the numbers shift, so re-measure after the fix), medium on phone sizes (read from Mantine size presets, not measured in a browser), and on dark rendering (read, not run).
