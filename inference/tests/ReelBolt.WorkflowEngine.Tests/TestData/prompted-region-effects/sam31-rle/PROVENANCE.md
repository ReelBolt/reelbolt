# Provenance — real `fal-ai/sam-3-1/video-rle` replay pack

These files are **vendor outputs replayed offline**. They are data, never code: nothing here is
executed, imported or trusted to be well-formed. The tests that read them treat every field as
untrusted input, and the reference decoder in `PromptedRegionFixtures.cs` validates each run
against the frame bounds before it uses it.

Ticket: `prompted-region-effects` T-002 (fixtures with exact ground truth + the bar instrument),
plan §7 ("Real model replay").

## Source media

`clips/cat-tabby.mp4` and `clips/cat-turn-a.mp4` are **AI-generated by the ReelBolt team**: short synthetic
clips of a cat, not footage of a real animal or person. They were generated with MiniMax (model as
recorded: `MiniMax-H3-Max`, per the project owner). They are test inputs only. The ReelBolt team provides them under this repository's licence.

**Deliberately not copied, for size:** the sibling ran the same endpoint on four clips. The
`black` and `turn-b` responses (1.6 MB + 3.2 MB) and their two clips (1.36 MB + 2.23 MB) were
left out — together they would have added ~8.4 MB to a pack whose coverage the two tabby/turn-a
fixtures already give: a clean track (R1/tabby), a stretch with the object fully hidden
(R1/turn-a), and a second seed on the same clip (R10/tabby). A later wave that needs the black cat
can copy the same way from the path in the table above.

## Layout facts the reference decoder pins (measured, not assumed)

* `rle[i]` is the frame-`i` mask of the run's single tracked object, and `objects[i][0].rle`
  equals it on every frame of all three files (checked while writing this pack).
* A run list is `"start length start length …"`, **0-based**, over a **row-major** index of a
  **768-wide** frame, i.e. the source's own width and height (768x1344). One run means "255 here",
  everything else is 0. Runs never overlap and never leave the frame.
* Decoding all three responses reproduces the sibling's own committed mattes
  (`.../trials/mattes/{R1/tabby,R1/turn-a,R10/tabby}.mkv`) **byte for byte** — the SHA-256 of the
  decoded grey8 frame stack is pinned in `decode-digests.json` and asserted by
  `PromptedRegionFixturesTests`.
* `metadata[i].box` / `boxes[i]` are `[centre-x, centre-y, width, height]`, **normalised**, not
  corner-anchored: reading them as `[x, y, w, h]` puts the box a half-height above the mask on
  every frame (measured mean error 842 px, 52 % of the frame diagonal), while the centre reading
  agrees to a few pixels. The vendor documents neither the anchoring nor the coordinate space; this
  was determined by decoding, and it is a finding the shipping client (T-003) needs.
* The vendor's own box and its own mask disagree on some frames: a 2–5 pixel sliver that crosses
  the right edge of the frame continues at column 0 of the next row, so the decoded bounding box
  spans the full width where the box does not. ≥ 98.5 % of every frame's mask pixels still fall
  inside the model's box grown by 2 px, and that fraction (not the bounding box) is what the test
  asserts.
