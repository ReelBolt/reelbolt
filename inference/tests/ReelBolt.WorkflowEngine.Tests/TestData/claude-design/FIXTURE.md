# Claude Design fixture

A synthetic Claude Design export for a fictional company ("Northwind Staffing"), shaped like a real
export (`_ds_manifest.json`, `"source": "spa"`). It describes no real company, product or brand.

## What is here

- `_ds_manifest.json` — the manifest: the namespace, 26 `components` entries, 3 starting points,
  3 `cards`, the `themes` array, the five token stylesheets as `globalCssPaths`, and 20
  representative `tokens` (base plus dark-scoped).
- `tokens/{fonts,colors,typography,spacing,elevation}.css` — a representative slice of base and
  dark token values. There are no remote `@import` lines.
- `components/core/Button.{d.ts,prompt.md}` and `components/overview/StatTile.{d.ts,prompt.md}` —
  type declarations and prompt prose, without fenced JSX examples.
- `SKILL.md` — front matter (`name`, `description`) and one prose line.
- `assets/*.png` — **synthetic 8×8 PNGs** generated by a script from flat colours. They are not
  anyone's artwork and carry no real imagery.

## What a real export has that this does not

Screenshots (`reference/`, `uploads/`), HTML (`*.card.html`, `guidelines/`, `ui_kits/`,
`thumbnail.html`, `.thumbnail`), JavaScript (`_ds_bundle.js`, `*.jsx`), SVG marks and large PNGs.
No file here is an executable or a markup document.

## Untrusted data

Everything here is untrusted input: the tests read it as bytes/text and never execute, import or
load anything from it. When refreshed from a real export, keep the same rules — no screenshots,
no `uploads/`, no HTML/JS, synthetic images only.
