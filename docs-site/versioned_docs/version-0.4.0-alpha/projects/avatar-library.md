# The workspace avatar library

The **Avatar library** holds the people and objects your workspace keeps for every project. An Owner or Admin of the workspace saves them there from a project; any member can then add them to their own projects. An item you add to a project stays linked to the library: its name, files and consent are managed in one place, and a change reaches every project that uses it.

The library is part of [Avatars](avatars.md) and is there only when avatars or objects are enabled in your workspace. Open it from **Settings > Avatar library**.

## Saving a person or an object to the library

You need to be an Owner or Admin of the workspace.

1. Open a project's **Avatars** tab and find a person or an object that is **Ready**.
2. Open its menu and choose **Save to the workspace library**.
3. Read the statement and confirm it. For a person this is a new consent, for the whole workspace: you confirm that the person agreed to their face, body and voice being used to make AI videos and pictures in any project of this workspace. For an object you confirm that the files show an object, a product or a place and no identifiable person, and that you may use them in any project of this workspace. For a person, also choose how long to keep it.
4. Choose **Save to the library**.

The project's avatar then becomes linked to the library item and shows the **Workspace library** badge. The workspace library can hold up to 100 people and 100 objects, each with its own name. An avatar that was itself imported from the library cannot be saved again.

## Adding a library item to a project

In the project's **Avatars** tab, choose **From the workspace library**. The list shows every person and object of the library, whether it can be used, and whether it is already in this project. Choose **Import**.

- Importing copies the item's files into the project's files, so they count toward your storage.
- The imported avatar is linked: its name, files and consent are managed in the library. In the project you can choose which of the project's voices a person speaks with (**Voice**), and **Remove from this project**.
- Your plan and the project's limits apply as for any avatar or object: a project holds up to 20 people and 20 objects.
- One library item can be in up to 50 projects at a time.

**Remove from this project** deletes the copies of its files made for this project. The item stays in the library and in every other project that uses it, and you can import it again later. Videos and pictures already made with it stay in the project.

## Variants in the library

A [variant](avatars.md#variants) you save to the library keeps its label and what sets it apart, and is listed under its original as, for example, **Car · Red**.

- Save the original first, then its variants: a variant whose original is already in the library goes under it. If you save the variant first, it is listed on its own until you save the original, then it moves under it.
- An original in the library can have up to 10 variants, and each label is used once per original. If another project already saved a "Red" variant of the same original, change this variant's label in its project before you save it.
- When you import a variant into a project that already has its original, it goes under the original there, like a variant made in the project, and it does not count toward the project's 20. If the original has no room for another variant there, or another of its variants already uses that label, the import is refused and nothing is copied. Imported on its own, a variant is an ordinary avatar of the project; importing its original later puts it under it.
- A variant's label and what sets it apart come with it from the library: a project that imports it cannot change them.
- Deleting an original, or withdrawing a person's consent, does not touch its variants: each keeps its own files and consent, and once the original is gone they stay in the library on their own.

## Managing the library

On **Settings > Avatar library** every member can see the items, their status and how many projects use each one. An Owner or Admin can also:

- **Rename or describe**: every project that uses the item shows the new name and description.
- **Confirm again**: for a person, renews the consent for the whole workspace and starts the keep-until date again from today; for an object, confirms its statement again. The files stay the same; to use other files, save a new item from a project.
- **Withdraw consent** (a person): the person can no longer be used in any project of the workspace, at once. The item and its copies in the projects are deleted automatically after 30 days, or sooner if you delete it. This cannot be undone.
- **Delete**: removes the item from the library and from every project that uses it, with the files copied there, and then tells you what was removed.

Videos and pictures already made with an item stay in their projects. Delete them yourself if the person asks you to.

When a person's keep-until date comes near, the workspace's Owners and Admins get an email a week before. If no one confirms it again, the item is deleted from the library and from every project.

## When a library item cannot be used

A library item, and every project avatar linked to it, cannot be used when:

- its consent was withdrawn;
- its keep-until date has passed (an Owner or Admin can confirm it again);
- in one project, one of its copied files was deleted or changed: remove it from that project and import it again.
